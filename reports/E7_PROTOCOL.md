# E7 — разложение сигнала по источникам информации: протокол

Зафиксирован 2026-11-03 **до расчётов**: на момент коммита этого файла ни одна модель E7 не обучалась и ни одна
метрика E7 не считалась. Вызовов LLM API нет. Изменения после первого прогона — только как отступления в
`reports/E7_REPORT.md` с причиной.

## 1. Вопросы

Сколько информации о провале задачи (`resolved = 0`) несёт каждый источник и что остаётся структуре траектории (S),
когда известны задача (T) и связка агент × модель (M):

- **(а)** AUROC внутри задачи для M в одиночку — сколько даёт узнавание модели;
- **(б)** прирост S над M внутри задачи: `M+S` против `M`;
- **(в)** прирост S над `T+M` по общему AUROC и по precision@k: `T+M+S` против `T+M`;
- **(г)** приросты A и R над `T+M+S`: `T+M+S+A` и `T+M+S+R` против `T+M+S`.

## 2. Популяция и метка

- `data/demo/runs.parquet`, `submitted == 1`: 7864 прогона, 500 задач, 16 связок (модель × версия агента),
  12 репозиториев. Порядок строк — по `run_id` (как в demo).
- Метка `y = 1 − resolved` (1 = задача не решена); риск — вероятность `y = 1`.
- Проверка устойчивости: та же популяция без задач `psf__requests-*` (8 задач, 127 прогонов) — 7737 прогонов,
  492 задачи; весь расчёт повторяется заново, включая разбиение на фолды.

## 3. Блоки признаков

| блок | содержание | обучение преобразования |
|---|---|---|
| **T** | TF-IDF текста `problem_statement` задачи + one-hot `repo` | TF-IDF — на текстах **уникальных задач** обучающего фолда; one-hot — на обучающем фолде (`handle_unknown="ignore"`) |
| **M** | one-hot связки (`model`, `agent_version`), 16 значений | обучающий фолд |
| **S** | 21 признак `M_struct+len` — список `FEATURES` из `demo_lib.features`, значения из `runs.parquet` | — |
| **A** | TF-IDF финального сообщения агента | TF-IDF — на прогонах обучающего фолда |
| **R** | TF-IDF всех рассуждений агента | TF-IDF — на прогонах обучающего фолда |

- **T.** SWE-bench Verified: `princeton-nlp/SWE-bench_Verified`, split `test`, из файла читаются **только** колонки
  `instance_id`, `repo`, `problem_statement`. Эталонный патч (`patch`), тесты (`test_patch`, `FAIL_TO_PASS`,
  `PASS_TO_PASS`) и `hints_text` не читаются и не используются. Все 500 `task_id` популяции должны найтись.
- **A.** Полный текст финального сообщения по правилам G0 (`clean_nl` + `pick_final`) из
  `data/interim/swebench_bashonly/trajectories.jsonl.gz` — без усечения до 1000 символов, которое есть в
  `runs.parquet` (`final_message`). Пустое сообщение — нулевой вектор.
- **R.** Тексты `clean_nl(text)` всех шагов агента (role = assistant) прогона, соединённые переводом строки
  (финальное сообщение входит). Источник тот же; усечения до 500 символов на шаг (как в `steps.parquet`) нет.
- **TF-IDF** во всех трёх блоках: `TfidfVectorizer(ngram_range=(1, 2), max_features=5000)`, остальные параметры по
  умолчанию (нижний регистр, стандартный токенизатор, нормировка строк L2). Маскирование маркеров утечки не
  применяется: это слова самого агента, а результаты скрытых тестов в траекторию не попадают (сообщение с отправкой
  адаптер отбрасывает).

## 4. Модели и обучение

Восемь моделей: `S`, `M`, `T`, `T+M`, `T+M+S`, `T+M+S+A`, `T+M+S+R`, `M+S`.

- Плотные блоки (S, one-hot M, one-hot repo) — `StandardScaler`, обученный на обучающем фолде. Блоки TF-IDF не
  масштабируются: `StandardScaler` не центрирует разреженные матрицы, а масштабирование без центрирования раздуло бы
  редкие n-граммы; строки TF-IDF уже нормированы L2. Это единственное отличие от «StandardScaler на всех признаках»
  в demo, и оно фиксируется здесь, до расчётов.
- `LogisticRegression(C=1.0, max_iter=5000)`, остальные параметры по умолчанию (L2, lbfgs). Подбора гиперпараметров нет.
- `GroupKFold(n_splits=5, shuffle=True, random_state=42)` по `task_id` — те же фолды, что в demo, одни для всех
  моделей; задача никогда не попадает одновременно в обучение и тест. Риск — out-of-fold.

## 5. Метрики

- **AUROC** — по объединённым out-of-fold рискам всей популяции (ранги, ничьи — средний ранг).
- **AUROC внутри задачи** — все пары (нерешённый, решённый) из одной задачи, объединённые по задачам (взвешенно по
  числу пар); ничья в паре — 1/2.
- **Brier** — среднее `(риск − y)²`.
- **precision@k**, k = 5 / 10 / 20 %: доля нерешённых среди `ceil(k·N)` прогонов с наибольшим риском (устойчивая
  сортировка по `−риск`).
- **same-unit weight** — доля пар внутри задачи среди всех пар (нерешённый, решённый) корпуса:
  `Σ_t n1_t·n0_t / (N1·N0)`.

## 6. Интервалы

Кластерный бутстрэп по задачам: 1000 выборок задач с возвращением, `seed = 42`, **одни и те же выборки для всех
моделей и метрик**; 95% интервалы — перцентильные. Разность моделей считается на каждой выборке, её интервал — по
этим разностям. В выборке: общий AUROC и Brier — по строкам выбранных задач (с повторами), внутри задачи — сумма
согласованных пар по выбранным задачам / сумма пар, precision@k — по `ceil(k·N_b)` строкам выборки. Точечные оценки
`S` совпадают с demo; интервал «внутри задачи» может немного отличаться от DEMO_REPORT.md, где бутстрэп шёл только по
задачам с обоими исходами.

## 7. Критерии ответов (до расчётов)

Для разности Δ (модель с источником минус модель без него): **прирост есть**, если нижняя граница 95% интервала Δ > 0;
**прирост не показан**, если интервал содержит 0; **отрицательный**, если верхняя граница < 0.

- **(а)** AUROC внутри задачи модели `M` с 95% интервалом. Узнавание модели даёт сигнал внутри задачи, если нижняя
  граница > 0.5. Описательно: доля «превышения над 0.5» модели `S`, которую даёт `M`:
  `(AUROC_M − 0.5) / (AUROC_S − 0.5)` внутри задачи.
- **(б)** Δ = AUROC внутри задачи (`M+S`) − (`M`); правило выше.
- **(в)** Δ = общий AUROC (`T+M+S`) − (`T+M`); правило выше. Δ precision@5/10/20% — то же правило, вторичные.
- **(г)** Δ_A = общий AUROC (`T+M+S+A`) − (`T+M+S`), Δ_R = (`T+M+S+R`) − (`T+M+S`); правило выше. Разности внутри
  задачи и precision@10% — вторичные.
- **Множественность.** Основное семейство — 4 разности: (б), (в)-AUROC, (г)-A, (г)-R. Для них дополнительно
  приводятся интервалы Бонферрони (98.75%); вывод «устойчив к множественности», если и этот интервал не содержит 0.
  Остальные разности и метрики — описательные, с 95% интервалами.
- **Устойчивость.** Ответы (а)–(г) пересчитываются без psf/requests; в отчёте — меняется ли категория ответа.
