# E12. Оценка сложности задачи по постановке для отбора — протокол

Дата: 2026-11-06. Протокол закоммичен до расчётов: на момент коммита эмбеддинги постановок не считались, ни одна
модель E12 не обучалась. Вызовов LLM API нет. Изменения после первого прогона допускаются только как отступления в
`reports/E12_REPORT.md`, с причиной.

## 1. Вопрос

Помогает ли компактное представление постановки задачи (T2) отбирать провальные прогоны на лидерборде сверх связки
агент × модель (M) и структуры траектории (S)?

В E7 блок T (TF-IDF постановки + one-hot `repo`, 5000 признаков) ухудшил модель: T+M+S дал 0.626 против 0.685 у M+S.
E12 проверяет, меняет ли это компактный T2: эмбеддинг постановки, сжатый до 32 компонент.

## 2. Популяция, метка, разбиение — как в E7

- **Популяция.** `data/demo/runs.parquet`, `submitted == 1`: 7864 прогона, 500 задач, 16 связок. Загрузка —
  `e7.load_population(False)`.
- **Метка.** `y = 1 − resolved`; риск — вероятность `y = 1`.
- **Фолды.** `GroupKFold(n_splits=5, shuffle=True, random_state=42)` по `task_id` (`e7.folds_of`) — те же фолды, что в
  E7 и demo.

## 3. Блок T2

- **Текст.** `problem_statement` из SWE-bench Verified (`data/raw/swebench_verified/tasks.parquet`, как в E7). Читаются
  только `instance_id`, `repo` и `problem_statement`.
- **Эмбеддинг.** Локальная модель `sentence-transformers/all-MiniLM-L6-v2`, загрузка и кодирование — как в E1
  (`embed.load_encoder("minilm")`, `embed._encode`):
  - `max_seq_length` 256: длинные постановки усекаются моделью, это свойство энкодера;
  - нормированные эмбеддинги, 384 измерения, CPU;
  - по одному эмбеддингу на задачу (500).
  - Ревизия модели записывается в отчёт.
- **PCA до 32 компонент.** Обучается в каждом фолде на уникальных задачах обучающего фолда (каждая задача один раз —
  как TF-IDF блока T в E7). Применяется ко всем задачам. `PCA(n_components=32, random_state=42)`, остальные параметры по
  умолчанию.
- **One-hot `repo`.** Обучается на обучающем фолде, `handle_unknown="ignore"`.
- **Подбора нет.** Число компонент, модель эмбеддинга и параметры не подбираются.

## 4. Модели

| модель | блоки |
|---|---|
| T2 | 32 компоненты PCA + one-hot `repo` |
| T2+M | T2 + one-hot связки (`model`, `agent_version`) |
| T2+M+S | T2 + M + 21 признак S (`demo_lib.features.FEATURES`) |
| M+S | M + S — для сравнения, воспроизводит E7 |

- Все блоки плотные. `StandardScaler` обучается на обучающем фолде на всех признаках модели.
- `LogisticRegression(C=1.0, max_iter=5000)`. Риск — out-of-fold.
- **Проверка воспроизведения.** M+S обязан дать общий AUROC 0.685 и AUROC внутри задачи 0.689 (E7, 3 знака). Иначе —
  остановка и описание причины.

## 5. Метрики и интервалы — как в E7

- **Метрики:**
  - общий AUROC;
  - AUROC внутри задачи;
  - precision@5/10/20%;
  - Brier.
- **ДИ.** Кластерный бутстрэп по задачам: 1000 выборок, seed 42, одни и те же выборки для всех моделей и метрик
  (`e7.evaluate` с этим набором моделей). 95% интервалы — перцентильные.
- **Разности:**
  - (T2+M+S) − (M+S) — основная;
  - (T2+M+S) − (T2+M) — прирост S над задачей и моделью, сравнение с E7 (в);
  - (T2+M) − M — описательно; M берётся из E7, повторно не обучается.
- **Внутри задачи.** T2 постоянен в пределах задачи, поэтому у T2 AUROC внутри задачи равен 0.5 по построению.
  Приводится для полноты.

## 6. Критерий (до расчётов)

**ДИ разности (T2+M+S) − (M+S) по общему AUROC выше нуля** (нижняя граница 95% интервала > 0).

Остальные разности и метрики — описательные, с 95% интервалами.
