# E8 — сигнал уровня прогона на повторных прогонах одной модели: протокол

Зафиксирован **до расчёта признаков и метрик** (2026-11-03). Вызовов LLM API нет.

## 1. Вопрос

В E7 у каждой связки был один прогон на задачу. Поэтому любая пара внутри задачи — пара разных моделей, и сигнал
структуры (`S`) внутри задачи не отделялся от того, какая модель работала. В исследовательском дополнении E7
(раздел 9 E7_REPORT) в парах моделей, близких по силе, `S` дал 0.544 [0.511; 0.576]; эту группу задали задним числом.

E8 сравнивает решённые и нерешённые прогоны **одной и той же настройки на одной и той же задаче**. Задача, модель,
каркас и температура в такой паре одинаковы, различается только ход прогона. Вопрос E8: различает ли структура
траектории такие прогоны.

**Что было просмотрено до протокола.**

- Связь признаков с метками не смотрелась.

**Единица** — настройка × задача.

**Популяция** — прогоны, чей патч был оценён тестами, то есть задача попала в `resolved_ids` или `unresolved_ids`
этого прогона.
- Метка: 1 — не решено, 0 — решено. Так же устроена `y` в demo и E7.
- Исключаются, с подсчётом по настройкам:
  - пустой патч (`empty_patch_ids`): провал очевиден без модели, аналог `submitted == 0`;
  - ошибка оценки (`error_ids`): метка неизвестна;
  - траектории, которые адаптер не смог разобрать или в которых нет ни одного сообщения агента — эти ещё и по
    классам.
- Прогоны, закончившиеся без финального сообщения агента (обрыв по лимиту), остаются в популяции. Их доля
  сообщается описательно.

## 3. Адаптер (`src/adapters/agentic_evals.py`)

Запись `detailed_predictions.jsonl` (`completion`) переводится в единую схему E0. Логика `demo_lib` не меняется.

- **Шаг** — сообщение `assistant`; `step_idx` идёт по порядку с 0.
- **Текст шага**: `reasoning_content` + `content` + команды шага в блоках ```` ```bash ````. Это то же правило, что
  в адаптере лидерборда (`swebench_bashonly._assistant_step`).
- **Команды шага** — из `tool_calls`:
  - `shell(cmd)` → строка `cmd` как есть;
  - `apply_patch(file, search, replace)` → `sed -i 's/<h(search)>/<h(replace)>/' <file>`, где `h` — первые 12
    знаков SHA-1 строки. Причина: `demo_lib` распознаёт правку и её файл по bash-команде. Перевод в правку на месте
    сохраняет три вещи:
    - класс «правка»;
    - целевой файл — для `n_files_edited` и `n_file_switches`;
    - идентичность патча — для `repeat_ratio` и `distinct_cmd_ratio`.

    Неудачный патч (`search string not found` и т. п.) остаётся правкой. На лидерборде точно так же классифицируется
    по команде `sed -i` без совпадения.
  - вызов несуществующего инструмента → команды нет: каркас его не исполнил.
- **Вывод инструмента** (`role = tool`) прикрепляется к своему шагу (`n_outputs`). Если вывод `shell` начинается с
  `command failed with exit code N` и N ≠ 0, тексту приписывается префикс `returncode: N`, как в адаптере
  лидерборда. Так считается `n_nonzero_rc`. У `apply_patch` кода возврата нет: его вывод считается выводом
  с кодом 0, как у `sed -i` без совпадения.
- **Сообщения `user`** после начала траектории (подсказки каркаса) не являются шагами.
- **`n_sent`** — число фрагментов `reason_sent` шага, через `src.segment.segment` с маскированием маркеров утечки
  `config/leak_markers.txt`. Так же построены demo-данные (`notebooks/build_demo_data.py`).
- **Признаки** — `demo_lib.features.trajectory_features`: 21 признак `S` (`FEATURES`) и 4 признака длины
  (`LEN`).

**Ручная проверка до метрик.**
- 20 траекторий, выбранных с seed 42: 7 + 7 + 6 по настройкам.
- По каждому шагу просматриваются:
  - исходный вызов инструмента;
  - полученная команда;
  - фаза;
  - первая строка вывода и признак ненулевого кода.
- Результат пишется в `reports/E8_adapter_check.md`.
- Если команды или фазы разобраны неверно, адаптер исправляется до расчёта метрик, а исправление описывается в отчёте.
- Если формат не позволяет выделить команды, работа останавливается.

## 4. Предсказатели

Модель везде одна: `StandardScaler` + `LogisticRegression(C=1, max_iter=5000)`, без подбора.

- **P1** — `S` (21 признак), обученная на корпусе лидерборда: `data/demo/runs.parquet`, `submitted == 1`, 7864
  прогона, все строки. Применяется к новым прогонам без дообучения.
- **P2** — `S`, обученная на новых данных.
  - Одна модель на три настройки вместе.
  - Out-of-fold: `GroupKFold(n_splits=5, shuffle=True, random_state=42)` по `task_id`. Все прогоны задачи во всех
    трёх настройках попадают в один фолд.
  - Обучение на всех прогонах популяции, включая единицы с одним исходом.
- **P3** — только длина (`LEN`: `n_steps`, `seg_len_steps`, `seg_len_sent`, `n_edits`), так же, как P2.

## 5. Метрики

Считаются по каждой настройке и в целом (все единицы трёх настроек).

- **AUROC внутри единиц.** Берутся все пары «нерешённый — решённый» внутри единицы. Метрика — доля пар, где риск
  нерешённого выше; ничья считается за 1/2. Пары всех единиц объединяются, то есть единицы взвешиваются по числу пар.
- **95% ДИ** — кластерный бутстрэп по единицам: 1000 выборок с возвращением, `default_rng(42)`, перцентили
  2.5–97.5. В целом — выборки по единицам всех трёх настроек. Разность P2 − P3 считается на тех же выборках.
- **Перестановочный тест.**
  - Метки перемешиваются внутри каждой единицы, риски не меняются. 1000 перестановок, отдельный генератор
    `default_rng(42)`.
  - Статистика — AUROC внутри единиц.
  - Альтернатива односторонняя: AUROC > 0.5.
  - p = (1 + число перестановок со статистикой ≥ наблюдаемой) / 1001.
- **Общий AUROC** — по всем прогонам настройки или всех трёх настроек.
- **Доля пар внутри единиц от всех пар:** Σ n1·n0 по единицам / (N1·N0).

## 6. Критерии

Проверяются на P2.

1. **Сигнал уровня прогона есть** в настройке, если выполнены оба условия:
   - нижняя граница 95% ДИ AUROC внутри единиц > 0.5;
   - перестановочный p < 0.05 с поправкой Холма по трём настройкам.

   В целом (все единицы) — то же, без поправки: это одна проверка на объединённом наборе.
2. **Практически значимый сигнал** — AUROC внутри единиц ≥ 0.60 (точечная оценка), по настройкам и в целом.
3. **Структура полезнее длины внутри единиц** — нижняя граница 95% ДИ разности P2 − P3 (AUROC внутри единиц) > 0;
   по настройкам и в целом.

P1 и P3 сообщаются теми же метриками (с поправкой Холма для их перестановочных p), но в критериях не участвуют.

## 7. Сравнение с E7

- Опорное значение — E7, раздел 9: `S` в парах моделей, близких по силе, |d| < 0.03 — 0.544 [0.511; 0.576].
- Сравнение описательное, без отдельного теста: P1 и P2 внутри единиц сопоставляются с этим значением и между собой.
  P1 — та же модель, что в E7. P2 обучена на повторных прогонах.
