# E9 — выбор лучшей из нескольких попыток по риску модели: протокол

Зафиксирован **до любых расчётов E9** (2026-11-03). Вызовов LLM API и новых скачиваний нет. Используются только
данные и код E8: `data/raw/agentic_evals`, `data/interim/agentic_evals`, `src/e8_repeats.py`, `demo_lib`.

## 1. Постановка

Агента запустили k раз на одной задаче. Сдать нужно одно решение, скрытых тестов нет. Правило выбора берёт попытку с
наименьшим риском.

**Вопрос:** растёт ли доля решённых задач по сравнению со случайным выбором среди попыток, отправивших результат?

## 2. Данные

- Три настройки E8: nano-agent × {Qwen3-32B, DeepSWE-Preview, devstral-2512}, температура 0.6.
- Каждая задача SWE-bench Verified (500) прогнана 10 раз: `run_0`…`run_9`.
- **Пул задачи** — все 10 попыток настройки на этой задаче.

**Попытка отправила результат** (`submitted`), если её патч непустой, то есть задача не в `empty_patch_ids` этого
прогона.

**Попытка решена** (`solved`), если задача в `resolved_ids`. Все остальные попытки считаются нерешёнными, как в
официальном подсчёте SWE-bench:
- пустой патч;
- `unresolved_ids`;
- `error_ids` — ошибка оценки. Такие попытки считаются отправившими результат: патч у них есть.

**Риск** нужен только попыткам, отправившим результат.
- Попытки с меткой (популяция E8, 13 778) берут признаки из `data/interim/agentic_evals/runs.parquet`.
- Для 34 попыток с ошибкой оценки признаки считаются тем же кодом E8 (`agentic_evals.to_record`, `step_dicts`,
  `demo_lib.trajectory_features`) из уже скачанных траекторий.

## 3. Оценки риска

Все оценки out-of-fold по задачам: ни одна не обучена на задаче, для которой выбирает. Модель везде
`StandardScaler` + `LogisticRegression(C=1, max_iter=5000)`.

- **P1** — `S` (21 признак `FEATURES`), обученная на корпусе лидерборда (`data/demo/runs.parquet`,
  `submitted == 1`). Без дообучения. Совпадает с P1 из E8, это проверяется равенством с
  `outputs/e8_runs.csv.gz`.
- **P2** — `S`, обученная **внутри своей настройки**.
  - `GroupKFold(n_splits=5, shuffle=True, random_state=42)` по `task_id` на популяции E8 этой настройки, строки
    упорядочены по `run_id`.
  - Обучение — только на попытках с меткой.
  - Попытка с ошибкой оценки получает риск от модели того фолда, куда попала её задача.

  **Отличие от E8.** В E8 P2 обучалась на трёх настройках вместе, поэтому её сохранённые оценки здесь не подходят по
  определению. P2 пересчитывается тем же кодом отдельно по каждой настройке.
- **P3** — только длина (`LEN`), так же, как P2.

## 4. Правила выбора из k попыток задачи

Ни одно правило, кроме oracle, не использует метки.

- **random** — случайная попытка из k. Ожидание считается точно: доля решённых среди k.
- **submitted-random** — случайная попытка среди отправивших результат. Если таких нет, случайная из всех.
  Ожидание тоже считается точно.
- **P1 / P2 / P3** — сначала остаются только попытки, отправившие результат, среди них выбирается наименьший риск.
  - При равенстве рисков выбор случайный, и считается точное ожидание: доля решённых среди попыток с одинаковым
    наименьшим риском.
  - Если отправивших нет — как random.
- **oracle (pass@k)** — задача решена, если решена хотя бы одна из k. Это верхняя граница.

## 5. Расчёт

- **k ∈ {2, 3, 5, 10}.**
  - Для k < 10 на каждую задачу берутся 200 случайных подвыборок по k попыток из 10. Генератор
    `np.random.default_rng(42)`, порядок k = 2, 3, 5.
  - Подвыборка — первые k позиций случайной перестановки номеров попыток.
  - Подвыборки одни и те же для всех правил и всех трёх настроек: номер попытки — это номер прогона `run_j`.
  - При k = 10 подвыборка одна — все попытки.
- **Значение задачи** для правила — среднее по подвыборкам.
- **Метрики области** (настройки или трёх вместе):
  - доля решённых задач = среднее значений задач;
  - Δ к submitted-random в процентных пунктах;
  - доля закрытого разрыва = (правило − submitted-random) / (oracle − submitted-random), это отношение средних.
- **95% ДИ** — кластерный бутстрэп по задачам: 1000 выборок задач с возвращением, отдельный `default_rng(42)` для
  каждой области. Выборки общие для всех правил и всех k, так что разности парные. Перцентили 2.5–97.5.
- **Области:**
  - каждая настройка — 500 задач;
  - три вместе — 1500 пар «настройка × задача», кластер — задача со всеми тремя настройками;
  - отдельными строками — те же области, ограниченные задачами со смешанным исходом. Смешанный исход — среди 10
    попыток настройки есть и решённые, и нерешённые: только там выигрыш возможен в принципе.

## 6. Критерии

Записаны до расчёта.

1. **Выигрыш есть** в настройке, если при k = 5 Δ(P2) > 0 подтверждается с поправкой Холма по трём настройкам.
   - Односторонний бутстрэп-p = (1 + число выборок с Δ* ≤ 0) / 1001.
   - После поправки Холма p должен быть < 0.025. Это то же самое, что нижняя граница скорректированного
     двустороннего 95% ДИ > 0.
   - Сообщается и нескорректированный 95% ДИ.
   - Для трёх настроек вместе — одна проверка, без поправки.
2. **Практически значимый выигрыш** — Δ(P2) ≥ +2 п.п. при k = 5 (точечная оценка), по настройкам и вместе.
3. **Структура лучше длины** — 95% ДИ разности P2 − P3 (доля решённых) при k = 5 выше нуля, по настройкам и вместе.
4. **Перенос с лидерборда работает** — критерий 1 выполняется для P1, со своей поправкой Холма по трём настройкам.

Основной результат — вся область (500 задач на настройку). Строки «только смешанный исход» — пояснение, в критериях
они не участвуют.

## 7. Гипотеза по E8

Это ожидание, а не критерий. Выигрыш будет у devstral-2512: там AUROC внутри единиц у P2 из E8 — 0.578. У
Qwen3-32B (0.531) и DeepSWE-Preview (0.499) он будет около нуля.

## 8. Связь с E8 (описательно)

По каждой настройке сопоставляются:
- Δ(P2) при k = 5;
- AUROC внутри единиц из E8 (P2, обучена на трёх настройках вместе);
- AUROC внутри единиц P2 и P3 этого этапа (обучены внутри настройки). Считаются кодом E8 (`unit_counts`) на
  популяции E8, без ДИ и тестов.
