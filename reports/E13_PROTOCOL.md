## 1. Перенос между поколениями агента

### 1.1. Популяция и поколения

Популяция E7 (`e7.load_population(False)`): 7864 прогона с `submitted == 1`, 500 задач, 16 связок. Метка
`y = 1 − resolved`.

| поколение | версии агента | связок | прогонов |
|---|---|---|---|
| v1 | 1.0.0, 1.9.1, 1.13.3, 1.15.0, 1.17.0, 1.17.1, 1.17.2 | 8 | 3908 |
| v2 | 2.0.0 | 8 | 3956 |

### 1.2. Разбиение

- **Направления:** v1 → v2 и v2 → v1.
- **Разбиение и по поколению, и по задаче.** Задачи в двух поколениях одни и те же. Чтобы задача никогда не попадала
  одновременно в обучение и тест (правило 2 AGENTS.md), берутся фолды E7 (`e7.folds_of`, `GroupKFold(5)` по
  `task_id`, seed 42).
- **В фолде k:** обучение — прогоны поколения A из задач вне фолда k; тест — прогоны поколения B из задач фолда k.
  Риск поколения B — out-of-fold по пяти фолдам.
- **Точка отсчёта (описательно):** B → B на тех же фолдах — обучение и тест внутри одного поколения.

### 1.3. Модели

- **S** — 21 признак `demo_lib.features.FEATURES`.
- **M+S** — one-hot связки + S. Связки поколения B в обучении не встречаются (`handle_unknown="ignore"`): в тесте
  one-hot M равен нулю, и после масштабирования это лишь общий сдвиг для всех тестовых прогонов. Фактически M+S в
  тесте ранжирует только по S, но с коэффициентами, обученными вместе с M. Это ожидаемое следствие, оно записывается.
- **Обучение** как в E7: `StandardScaler` на обучающих строках + `LogisticRegression(C=1, max_iter=5000)`, подбора нет.

### 1.4. Метрики и ДИ

- **Метрики** — на прогонах тестового поколения: общий AUROC, AUROC внутри задачи, precision@10%; Brier — для
  полноты.
- **ДИ** — кластерный бутстрэп по задачам: 1000 выборок, seed 42, общие для всех моделей направления (код E7).
- **Разность** B → B минус A → B — с ДИ на тех же выборках, описательно.

### 1.5. Критерий

**Перенос работает**, если нижняя граница 95% ДИ общего AUROC S в направлении v1 → v2 больше 0.6.

### 1.6. Проверка формата логов (описательно)

- **Признаки:** `n_steps`, `share_verify`, `has_any_verification`, `verif_after_last_edit`, `phase_bigram_entropy`.
- **Модели, которые есть в обоих поколениях:**
  - claude-sonnet-4-5: v1.13.3 и v2.0.0 `@high`;
  - gemini-3-pro-preview: v1.15.0 и v2.0.0 `@high`.
- **Оговорка.** В v2 у обеих режим `@high`, поэтому различие поколений смешивает формат агента с режимом
  рассуждения. Это записывается.
- **Сравнение.** Для каждой модели и признака — на задачах, отправленных в обоих поколениях: среднее и медиана по
  поколениям, стандартизованная разность средних SMD (`(m2 − m1) / sqrt((s1² + s2²)/2)`), статистика
  Колмогорова–Смирнова D.
- **Правило, до расчётов.** Различие **заметное**, если |SMD| ≥ 0.5; умеренное — 0.2 ≤ |SMD| < 0.5. Заметное различие у
  одной и той же модели записывается как эффект формата (с оговоркой о `@high`), а не модели.
- **Масштаб для сравнения.** Медиана |SMD| между разными связками внутри одного поколения (все пары связок в v1 и все
  пары в v2) — по каждому признаку.

## 2. Предсказуемость против силы модели (описательно, без критерия)

- **Для каждой из 16 связок:**
  - AUROC S на её прогонах — по OOF-рискам E7 (`outputs/e7_oof_risk.csv.gz`, популяция `all`, модель S);
  - доля решённых среди её прогонов (`submitted == 1`).
- **Корреляция Спирмена** ρ между ними. ДИ — бутстрэп по связкам: 1000 выборок 16 связок с возвращением, seed 42,
  перцентили 2.5 и 97.5.
- **Сравнение с литературой.** ρ = −0.662 (arXiv 2610.05572, по данным автора). Статью я не проверял; в отчёте
  приводится только это значение.

### 3.3. Лидерборд: модели и критерий

- **Модели:** P, S+P, M+S+P, M+S. Популяция, фолды, обучение, метрики и бутстрэп — как в E7: общий AUROC, внутри
  задачи, precision@5/10/20%, Brier; 1000 выборок задач, seed 42, общие для всех моделей.
- **Воспроизведение.** M+S обязан дать 0.685 / 0.689 (E7). Иначе — остановка.
- **Критерий.** ДИ разности (M+S+P) − (M+S) по общему AUROC выше нуля (нижняя граница 95% > 0).
- **Отдельно, описательно:** та же разность по AUROC внутри задачи; (S+P) − S.

### 3.4. KTH, devstral-2512 (описательно)

- **Популяция** — попытки настройки nano-agent × devstral-2512 с меткой (как E8 / E10).
- **Модели S и S+P** обучаются внутри настройки на фолдах E9: `GroupKFold(5, shuffle, 42)` по задаче на популяции
  E8; код E10 `kth_risks`.
- **Метрика** — AUROC внутри единицы (задачи); бутстрэп по единицам, 1000, seed 42 (код E8). Разность (S+P) − S — с ДИ.
- **Воспроизведение.** S внутри единиц обязан совпасть с E10 (0.561, 3 знака).

## 3a. Отступление до расчётов блока P (2026-11-08)

Найдено при первом извлечении диффов, до любой метрики блока P.

- **Почему.** Локально лежат только около 350 из 7864 `traj.json` лидерборда: полный набор, 7.5 ГБ, обрабатывался на
  Kaggle. Скачать его заново нельзя без подтверждения автора — это больше 3 ГБ.
- **Новый источник диффа лидерборда** — `logs/<task>/patch.diff` из того же бакета `s3://swe-bench-submissions/`.
  - Это патч самой модели в том виде, в каком он ушёл на оценку, а не эталонный патч.
  - Скачиваются только файлы `patch.diff` (мегабайты на прогон).
  - `test_output.txt`, `job-output.json` и прочие логи оценки не скачиваются и не используются.
- **Проверка.** На прогонах, чей `traj.json` есть локально, `patch.diff` сравнивается с `info.submission`. Сообщается доля
  совпадений; сравнение — после удаления концевых пробельных символов.
- **Если `patch.diff` нет** — берётся локальный `info.submission`, если он есть; иначе дифф пустой. Число таких случаев
  записывается в отчёт.
