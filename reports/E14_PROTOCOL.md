# E14. Перенос на новые модели того же формата агента — протокол

Дата: 2026-11-08. Протокол закоммичен до расчётов: на момент коммита новые прогоны не разбирались целиком, признаки S
и P по ним не считались, ни одна модель E14 не обучалась. Вызовов LLM API нет. Изменения после первого прогона
допускаются только как отступления в `reports/E14_REPORT.md`, с причиной. Скрипт: `src/e14_new_models.py`. Это
последний этап.

## 1. Данные

- **Четыре новых прогона** bash-only, скачаны на E13 в `data/raw/swebench_bashonly_new/` — по 500 траекторий и меток
  (`report.json`, тот же источник, что у корпуса):
  - `20260217_mini-v2.0.0_claude-4-5-opus-high`;
  - `20260217_mini-v2.0.0_claude-4-6-opus`;
  - `20260217_mini-v2.0.0_gpt-5-2-high`;
  - `20260219_mini-v2.0.0_gpt-5-2-codex`.
- **Разбор тем же кодом:**
  - адаптер E0 `swebench_bashonly.iter_records` / `parse_trajectory` с теми же правилами исключения
    (`config/datasets.yaml`: инфраструктурные статусы);
  - затем `notebooks/build_demo_data.record_rows` — признаки S через `e5.process_record`, `submitted` =
    `exit_status == "Submitted"`, метка `resolved` из `report.json`;
  - в анализ идут только `submitted == 1`.

### 1.1. Что известно до протокола: GPT-5.2 тем же кодом не разбирается

Перед написанием протокола адаптер проверен на первых 40 траекториях каждого прогона:
- **Claude Opus 4.5 и 4.6** — разбираются все 40;
- **GPT-5.2 high и GPT-5.2-codex** — все 40 исключены с причиной `unsupported_format:responses_api`: траектории записаны
  в формате OpenAI Responses API, адаптер E0 его не поддерживает.

Решение до расчётов:
- **Основной анализ — на двух связках Claude Opus** (4.5 high и 4.6): они разбираются тем же кодом.
- **Прогоны GPT-5.2 исключаются из признаков S** с этой причиной; число исключённых записывается.
- **Конвертер не пишется.** Отдельный разбор Responses API был бы новым кодом и сам задавал бы границы шагов. E13
  показал, что признаки S зависят от формата логов, так что это смешало бы перенос с эффектом формата.
- **Описательная часть** (доля решённых, доля пустых диффов, п. 4) для GPT-5.2 считается без разбора траектории: по
  `report.json`, `info.exit_status` и диффу.

## 2. Проверка воспроизведения кода

Перед расчётами `record_rows` применяется к 50 случайным прогонам корпуса (seed 42) из
`data/interim/swebench_bashonly/trajectories.jsonl.gz`. Все 21 признак S, `submitted` и `resolved` обязаны совпасть с
`data/demo/runs.parquet` (допуск 1e-9). Иначе — остановка.

## 3. Обучение, тест, метрики

- **Обучение** — 8 связок v2.0.0 корпуса (3956 прогонов, `submitted == 1`).
- **Тест** — новые связки (п. 1.1: Opus 4.5 high, Opus 4.6), `submitted == 1`.
- **Разбиение по задаче, как в E13.** Фолды E7 (`e7.folds_of` на популяции корпуса, `GroupKFold(5)` по `task_id`,
  seed 42); задача нового прогона получает фолд своей задачи в корпусе. В фолде k: обучение — прогоны v2 корпуса из
  задач вне фолда k; тест — новые прогоны из задач фолда k. Риск — out-of-fold.
- **Модели.** S (21 признак) и S+P (S + 6 признаков P из E13, те же преобразования). `StandardScaler` +
  `LogisticRegression(C=1, max_iter=5000)`, подбора нет.
- **P новых прогонов** — из `logs/<task>/patch.diff`, как в E13 (п. 3a протокола E13).
  - Скачиваются только `patch.diff`, для всех четырёх прогонов.
  - Для двух Opus — сверка с `info.submission` локальных `traj.json`.
- **Метрики** — по каждой новой связке и вместе:
  - общий AUROC;
  - precision@10%;
  - AUROC внутри задачи — только вместе: пары только между новыми связками; у одной связки одна попытка на задачу,
    так что по одной связке эта метрика не определена;
  - Brier — для полноты.
- **ДИ** — кластерный бутстрэп по задачам, 1000 выборок, seed 42 (код E7 / E13), общие для моделей внутри одной
  оценки.
- **Верхняя граница (описательно).** S и S+P, обученные внутри тех же новых связок на тех же фолдах: обучение — новые
  прогоны вне фолда k, тест — новые прогоны фолда k. Плюс разность «верхняя граница − перенос» для S с ДИ.

## 4. Критерий (до расчётов)

**Перенос на новые модели того же формата работает**, если нижняя граница 95% ДИ общего AUROC S (обучение на 8
связках v2.0.0, тест на новых связках вместе) больше 0.6.

## 5. Описательно

- **По каждому из четырёх новых прогонов:** число траекторий, исключённых и причины, `submitted == 1`, доля решённых
  среди отправленных, доля пустых диффов среди отправленных.
- **Корреляция Спирмена** «доля решённых — AUROC S» по связкам:
  - 16 связок корпуса — AUROC S по OOF E7, как в E13;
  - плюс разобранные новые связки — AUROC S переноса;
  - ДИ — бутстрэп по связкам, 1000, seed 42.
  - Число связок — 16 + число разобранных новых, то есть 18, если GPT-5.2 не разобран. Это записывается.
  - Проверка: с AUROC верхней границы вместо переноса.
