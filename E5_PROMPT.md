# Задача для Claude Code: тест E5 — достоверность утверждений агента

## Контекст

Репозиторий уже содержит: адаптеры траекторий SWE-bench Verified (7975 прогонов, 16 связок
«агент × модель»), сегментацию и кэш эмбеддингов (`data/emb/reason_sent/`), признаки хаотичности
(`outputs/features.csv.gz`), разметку утверждений (`outputs/g0_final_messages.csv`), фолды
(`outputs/folds.csv`).

Новая задача отличается от E4 **подпопуляцией и меткой**:
- подпопуляция — только траектории, где агент утверждает, что задача выполнена (`has_claim == True`,
  ~2877 прогонов);
- метка — достоверно ли утверждение, то есть `label` из автотестов бенчмарка.

Уже измерено (не переделывать):
- H и C по всей траектории на этой подпопуляции → AUROC 0.528;
- `verif_after_last_edit` поодиночке → 0.555; `n_verifications` → 0.558.

E5 проверяет две гипотезы и **сравнивает их**.

- **H1.** Энтропия и сложность, посчитанные не по всей траектории, а по её **сегменту после
  последнего изменения кода** (фаза проверки и обоснования), разделяют достоверные и недостоверные
  утверждения.
- **H2.** Структурные признаки процесса (наличие и характер верификации, порядок фаз, повторы)
  разделяют их.

Отрицательный результат по любой из гипотез — допустимый исход. Не подгонять.

## Жёсткие требования

1. Новый модуль `src/e5_claims.py`, команда `python -m src.cli e5`. Существующие скрипты не менять.
2. **Без оракула.** Эталонный патч (gold patch) в признаках основной модели не используется.
   Если сделаешь отдельный анализ с ним — только как верхняя граница, в отдельной таблице,
   с явной пометкой.
3. Группировка по `task_id` во всех разбиениях (`GroupKFold`, 5 фолдов). Доверительные интервалы —
   бутстрэп по задачам, 1000 итераций.
4. Фиксированная длина окна при расчёте энтропии. Траектории короче окна исключаются,
   число исключённых логируется отдельно по классам.
5. seed = 42, версии закреплены.
6. Логистическая регрессия с L2 и стандартизацией. Без подбора гиперпараметров.

## Этап 1 (шлюз). Аудит длины сегмента

Определить сегмент: все фрагменты после **последнего** шага-правки до конца траектории.

Правила разметки шагов (те же, что в G0):
- **правка** — `apply_patch`, `edit`, `str_replace`, запись в файл, `>` / `>>`, `sed -i`, heredoc;
- **верификация** — `pytest`, `python -m pytest`, `python -m unittest`, `tox`, `make test`,
  `./run_tests`, запуск скрипта, содержащего `assert`;
- остальное — прочее.

Посчитать и вывести в `reports/E5_segment_audit.md`:
- распределение длины сегмента в **шагах** и в **предложениях** (мин / 25% / медиана / 75% / 90%);
- то же отдельно для достоверных и недостоверных утверждений;
- долю траекторий, где сегмент пуст (правка была последним действием).

**Решение по шлюзу:**
- медиана ≥ 200 предложений → H1 считать при N = 200, d = 4;
- медиана 100–200 → N = 100, d = 4;
- медиана 50–100 → N = 50, d = 3, в отчёте указать, что оценка смещена;
- медиана < 50 → **H1 на сегменте не проверяется**, зафиксировать это как результат
  (аппарат неприменим к объекту такой длины) и перейти к этапу 3.

Обоснование порогов: смещение перестановочной энтропии на коротких рядах измерено ранее
(белый шум при n = 20, d = 4 даёт H = 0.78 вместо 1.0; стандартное требование в литературе — n > 5·d!).

## Этап 2. H1 — хаотичность сегмента проверки

Для каждой траектории подпопуляции построить ряд из сегмента (проекции те же, что в E2:
`cos_step`, `cos_task`, `pca1`), посчитать `H`, `C` при выбранных N и d.

Модели (все на подпопуляции заявивших успех):
- `M_len` — только длина: число шагов, число предложений сегмента, число правок;
- `M_chaosSeg` — только `H`, `C` сегмента;
- `M_chaosFull` — `H`, `C` по всей траектории (уже посчитаны, взять из `features.csv.gz`);
- `M_chaosSeg+len`.

**Критерий H1:** нижняя граница 95% ДИ разности AUROC(`M_chaosSeg+len`) − AUROC(`M_len`) > 0.

Дополнительно: корреляция Спирмена `H` сегмента с его длиной. Высокая корреляция означает,
что признак вторичен по отношению к длине.

## Этап 3. H2 — структурные признаки

Считать на той же подпопуляции, **только по процессу**, без эталонного патча:

Верификация:
- `has_any_verification`, `n_verifications`;
- `verif_after_last_edit`, `n_verif_after_last_edit`;
- `verified_before_first_edit` (проверял ли до правки);
- `n_steps_after_last_edit`.

Порядок фаз:
- доли фаз (правка / верификация / прочее);
- число переходов между фазами;
- **энтропия Шеннона по распределению биграмм фаз** — дешёвый структурный аналог меры
  беспорядка, считать обязательно;
- доля шагов до первой правки (сбор контекста).

Повторы и ошибки:
- `repeat_ratio` — доля одинаковых подряд идущих команд;
- `n_distinct_commands / n_steps`;
- доля команд с ненулевым кодом возврата;
- число уникальных файлов, затронутых правками; число переключений между файлами.

Модели:
- `M_struct` — только структурные;
- `M_struct+len`;
- `M_all` — структурные + `H`, `C` сегмента + длина.

**Критерий H2:** AUROC(`M_struct+len`) ≥ 0.65 с нижней границей ДИ выше AUROC(`M_len`).

**Критерий вклада хаотичности:** нижняя граница ДИ разности AUROC(`M_all`) − AUROC(`M_struct+len`) > 0.

## Этап 4. Обязательные контроли

1. **Смешение со сложностью задачи.** Повторить сравнение внутри задач, где есть достоверные
   и недостоверные утверждения по одной задаче. Сообщить число таких задач.
2. **Перенос между моделями.** Обучить на одних семействах моделей, проверить на других.
   Сообщить падение AUROC.
3. **Перенос между версиями агента.** v1.x → v2.x и обратно.
4. **Калибровка** итоговой модели: мера Бриера, кривая надёжности.
5. **Важность признаков** для `M_all`: коэффициенты регрессии и значения Шепли.
