# 04. Методы

## 1. Постановка

- **Достоверность выполнения** (veracity of task completion): агент отправил патч и тем заявил, что задача решена;
  достоверно ли это заявление — решают скрытые тесты бенчмарка, недоступные агенту.
- **Модель оценки** по траектории выдаёт риск того, что сданный результат не решает задачу. Применение — ранжирование
  сданных результатов для выборочной проверки человеком (triage).
- **Оценка после отправки, по полной траектории.** Эталонный патч и скрытые тесты как вход не используются. Это отличие
  от ранней остановки и от предсказания по префиксам (`02_related_work.md`).

## 2. Признаки

| блок | что это | источник |
|---|---|---|
| `S` — структура траектории | длина (шаги, предложения рассуждений), доли фаз правка / проверка / прочее, переходы, повторы команд, доля ненулевых кодов возврата, признаки после последней правки; {{rev.s21|v}} столбец, из них {{rev.s20|v}} разных (`seg_len_steps` = `n_steps_after_last_edit`) {{src:rev.s21}} | `demo_lib/features.py` |
| `LEN` — длина | признаки длины из `S`; база «модель + длина» | `demo_lib/features.py` |
| `N` — число шагов | log числа шагов; база «модель + log шагов» | E15 |
| `M` — модель | one-hot связки «агент × модель» | E7 |
| `O` — исходы собственных проверок агента | {{e10.o19}}: последняя проверка тестами проекта и любая проверка (pass, fail, error_env, error_code, script_ok, script_fail, unknown), число и доля упавших после первой правки, правка после последнего прохода, противоречие «заявил успех при упавшей проверке» | E10 |
| `P` — признаки патча (без эталона) | размеры итогового диффа, новые файлы, файлы вне пакета | E13 |

**Разметка фаз.** Каждый шаг агента относится к фазе по командам: правка (`sed -i`, запись в файл, `apply_patch`),
проверка (запуск тестов и скриптов), прочее. Известные ограничения (рецензия, §5; `reports/E8_adapter_check.md`):
- правила зависят от формата команд каркаса (например, `django test`, `.write(`), поэтому признаки сдвигаются между
  форматами логов (E13);
- на повторах KTH `apply_patch` переводится в `sed -i`; неудачные и отклонённые каркасом правки считаются правкой;
- у агентов без запуска тестов (Qwen3-32B) признаки проверки почти постоянны.

**Разбор исходов проверок (`O`).** Правила разбора проверены вручную в четыре раунда на выборках шагов
(`reports/E10_parser_check.md`); доля `unknown` у devstral-2512 — {{e10.unknown.dev}} проверок из-за обрезки вывода
каркасом.

## 3. Модель

Стандартизация признаков + логистическая регрессия (`C = 1`). Предсказание — вне обучающей выборки: `GroupKFold` по
задаче (на повторах — по задаче внутри настройки или на объединении настроек), риск каждого прогона получен моделью,
не видевшей его задачу. Бустинг не лучше регрессии (`09_negative_results.md`).

Схемы обучения на повторах KTH: **T1** — одна модель на обе настройки; **T2** — своя модель на каждую настройку; T3 —
T2 только на законченных попытках. T2 используется в E9, E10, E16; T1 — в E8.

## 4. Три уровня оценки

| уровень | какие пары | что измеряет | где |
|---|---|---|---|
| общий AUROC | все пары (нерешённый, решённый) | смесь сложности задачи, модели и попытки | лидерборд |
| внутри задачи | пары одной задачи, пулом по задачам | модель и попытка; сложность задачи снята | лидерборд |
| внутри единицы | пары попыток одной единицы (одна модель, одна задача), пулом | только попытка | повторы KTH |

Равные риски в паре засчитываются как половина согласованной пары. Внутри единицы дополнительно: все пары и пары законченных попыток (обе закончились
сообщением агента без вызова инструмента), база «попытка не закончена».

## 5. Метрики

- **AUROC** трёх уровней (§4).
- **precision@k и recall@k** при бюджете проверки k% прогонов (precision@5%, precision@10%, precision@20%; recall@10%); равенства на границе отбора — по
  ожиданию (исправление рецензии, М9). Наибольший возможный recall@10% при доле нерешённых P_ne —
  {{e15.ne.maxrec}}.
- **Выбор из k попыток:** доля решённых задач при выборе попытки с наименьшим риском; точное ожидание по равенствам;
  база — случайная попытка среди отправивших и среди законченных; {{e9.nsub}} случайных подмножеств на задачу.
- **Разложение дисперсии:** смешанная логистическая модель `logit P(не решено) = μ_настройка + a_задача +
  c_задача×настройка`, максимум правдоподобия (квадратура Гаусса–Эрмита); латентные доли с `π²/3` для попытки;
  наблюдаемая шкала — дисперсионный анализ средних единиц.
- **Потолок AUROC внутри единицы** из шума оценки на побайтно одинаковых патчах (модель симметричного шума с
  вероятностью ε).

## 6. Интервалы и проверки

- **Кластерный бутстрэп:** по задачам (лидерборд) или по единицам (повторы), {{e8.boot}}. Разности — на тех же
  выборках.
- **Перестановочный тест** внутри единиц (E8, E10) и поправка Холма по настройкам.
- **Протоколы до расчётов.** Каждый этап E7–E16 имеет протокол, закоммиченный в git до первого расчёта или вызова API;
  порядок «протокол → первый вызов → результаты» сведён в `docs/EXPERIMENTS.md` и подтверждается последовательностью
  коммитов, отправленных на GitHub. E15 — сводный этап (часть чисел известна из рецензии), E16 — подтверждающий.
  Отступления записаны в протоколах; главное — исключение DeepSWE-Preview (`03_data.md`).
- **Независимая рецензия** (`review/REVIEW.md`) воспроизвела основные числа своим кодом метрик.
- **Ограничение:** время коммита задаёт автор; гарантирован только порядок коммитов.
