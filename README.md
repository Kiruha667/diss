## Задача

Автономный агент в конце работы сообщает, выполнил ли он задачу. Измерено, что это сообщение
не связано с фактическим результатом. Работа строит модель, оценивающую достоверность такого
утверждения по ходу выполнения задачи, а не по тексту самого утверждения.

Метка исхода берётся из прогона автотестов бенчмарка — внешняя, объективная, ручной разметки
не требует.

## Данные

- Траектории с лидерборда **SWE-bench Verified**, каркас mini-SWE-agent.
- **7975 траекторий**, 500 задач, 16 связок «агент × модель», 7 семейств моделей.
- Доля провалов 0.34 (2707 траекторий).
- 337 задач имеют прогоны обоих классов — это позволяет сравнивать поведение **внутри одной
  задачи**, снимая смешение со сложностью.
- Подпопуляция для основной модели — **2877 траекторий**, где агент заявил об успехе.

## Основные результаты

### 1. Самоотчёт агента неинформативен

| Показатель | Значение |
|---|---|
| Утверждение об успехе среди провальных траекторий | 36.9% [35.2; 39.0] |
| То же среди успешных | 35.6% |
| Разность | −1.3% [−3.7; 1.1] — неотличима от нуля |
| Взаимная информация «утверждение × исход» | 0.0001 бита при энтропии исхода 0.92 бита |
| Признание неудачи среди 2707 провалов | 8 траекторий |

Следствие: оценщик, читающий финальное сообщение агента — человек или LLM-судья — обманывается
систематически.

### 2. Энтропийно-сложностный анализ семантических траекторий: отрицательный результат

Построены семантические траектории (сегментация на предложения → эмбеддинг → проекция
в одномерный ряд → перестановочная энтропия и статистическая сложность по Бандту–Помпе).
Сетка из 88 конфигураций: 2 способа сегментации × 4 проекции × длины окна 50–400 × порядок
паттернов 3 и 4.

| Проверка | AUROC |
|---|---|
| Прирост над моделью на длине (заданная заранее конфигурация) | Δ 0.014 [−0.004; 0.031] |
| То же при вложенном выборе конфигурации | Δ 0.010 [−0.007; 0.028] |
| H, C на подпопуляции заявивших успех | 0.528 |

Критерий, заданный до эксперимента, не выполнен. После поправки Бенджамини–Хохберга значимы
3 конфигурации из 88, все с приростом в пределах 0.02.

### 3. Аппарат неприменим к фазе проверки — измеренная причина

Предполагалось, что считать надо не по всей траектории, а по сегменту после последнего
изменения кода, где агент проверяет результат и решает, объявлять ли успех.

Медианная длина этого сегмента — **23 предложения**. Требование к оценке перестановочной
энтропии — n > 5·d! (120 точек при d = 4). Симуляция: белый шум при n = 20 и d = 4 даёт
H = 0.78 вместо 1.0, то есть оценка систематически смещена вниз.

Решение: зафиксировать неприменимость как результат, а не считать на недостаточной длине.

### 4. Устойчивость признаков к выбору энкодера

Значения H и C, посчитанные на одних траекториях двумя энкодерами (all-MiniLM-L6-v2 и
nomic-embed-text-v1.5), коррелируют между собой на ρ ≈ 0.31, причём корреляция растёт с длиной
окна: 0.17 при N = 50 → 0.43–0.51 при N = 400.

Часть расхождения объясняется шумом оценки, часть, возможно, структурная. Вопрос касается
сопоставимости результатов между исследованиями, использующими подобные признаки.

### 5. Модель на структуре траектории

| Модель | AUROC |
|---|---|
| Только длина траектории | 0.640 [0.615; 0.663] |
| **Структурные признаки + длина** | **0.684 [0.659; 0.709]** |
| Прирост | 0.044 [0.025; 0.064] |
| Внутри задач: структурные | 0.646 |
| Внутри задач: только длина | 0.589 |
| Медианное падение при переносе между семействами моделей | 0.011 |
| Калибровка (мера Бриера) | 0.203 против 0.227 у константной модели |

**Сильнейший признак — энтропия биграмм фаз действий** (коэффициент −0.413, средний |SHAP| 0.315):
у недостоверных утверждений 0.555, у достоверных 0.624. Агент, ошибающийся и не замечающий
этого, действует монотоннее — реже переключается между локализацией, правкой и верификацией.

Таким образом, энтропийный подход подтверждается, но на уровне структуры действий,
а не семантической траектории.

## Методика

**Разметка.** Правиловое выделение финального утверждения агента (с отсечением служебных токенов
протокола сдачи), два набора регулярных выражений — утверждение об успехе и признание неудачи;
правиловая разметка шагов на фазы: локализация, правка, верификация, прочее.

**Признаки.** Верификационные (наличие и положение проверки относительно правок), последовательностные
(доли фаз, число переходов, энтропия Шеннона по биграммам фаз), повторяемость, объёмные
и файловые.

**Модели.** Логистическая регрессия с L2 и стандартизацией. Сравниваются вложенные модели
(только длина / только структура / всё), чтобы измерить вклад каждой группы признаков.
Гиперпараметры не подбираются: работа сравнивает признаки, а не классификаторы.

**Протокол оценки.**
- `GroupKFold` по `task_id` — одна задача не попадает одновременно в обучение и тест.
- Кластерный бутстрэп по задачам, 1000 итераций, для доверительных интервалов.
- Анализ внутри задач — контроль смешения со сложностью задачи.
- Поправка Бенджамини–Хохберга при множественных сравнениях конфигураций.
- Проверка переноса между семействами моделей и версиями агента.
- Оценка калибровки: мера Бриера, кривые надёжности.
- Теоретико-информационный анализ: взаимная информация.
- Фиксированная длина окна при расчёте энтропии; исключённые траектории логируются по классам.

## Структура репозитория

```
AGENTS.md                спецификация основного пайплайна (E0–E4)
G0_PROMPT.md             спецификация теста G0
E5_PROMPT.md             спецификация теста E5
config/                  паттерны утверждений, маркеры, конфигурация источников
src/
  adapters/              приведение траекторий к единой схеме
  segment.py             сегментация и очистка текста
  embed.py               эмбеддинг с кэшированием
  project.py             проекции траектории в одномерный ряд
  chaos.py               перестановочная энтропия, статистическая сложность
  features.py            признаковое описание
  g0_false_success.py    разметка утверждений
  e5_claims.py           структурные признаки и модели
  stats.py               статистические тесты
  cli.py                 единая точка входа
reports/                 отчёты по этапам
outputs/                 таблицы результатов
tests/                   тесты кода
```

Сырые данные и кэш эмбеддингов в репозиторий не включены (см. `.gitignore`).

### Воспроизведение

```
pip install -r requirements.txt
python -m src.cli inventory
python -m src.cli build --seg reason_sent
python -m src.cli features --seg reason_sent --proj cos_step --N 200 --d 4
python -m src.cli stats --all
python -m src.cli g0
python -m src.cli e5
```

Все случайные операции с фиксированным seed = 42.

## Ограничения

- Один бенчмарк (SWE-bench Verified) и один каркас агента (mini-SWE-agent); перенос на другие
  домены не проверен.
- Только англоязычные траектории.
- Разметка утверждений правиловая; валидирована ручной проверкой стратифицированной выборки
  (`outputs/g0_manual_sample.csv`), число 36.9% является нижней границей.
- Сравнение версий агента v1.x и v2.x осложнено различием форматов логирования.
- Признаки хаотичности зависят от выбора энкодера (см. результат 4).
